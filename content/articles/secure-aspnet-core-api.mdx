Security is easiest to get right when it is the default rather than something each endpoint has to remember. This article builds a baseline for an ASP.NET Core API where forgetting a step fails *closed*.

## Introduction

<Statement type="opinion">
The single most valuable setting in an ASP.NET Core API is a **fallback authorization policy**. It turns "did someone remember `[Authorize]`?" into "did someone explicitly opt out?".
</Statement>

## Example

```csharp title="Program.cs"
builder.Services.AddProblemDetails();

builder.Services.AddAuthorization(options =>
{
    // Every endpoint requires an authenticated user unless it opts out with AllowAnonymous().
    options.FallbackPolicy = new AuthorizationPolicyBuilder()
        .RequireAuthenticatedUser()
        .Build();
});

builder.Services.AddRateLimiter(options =>
{
    options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;
    options.AddFixedWindowLimiter("default", limiter =>
    {
        limiter.PermitLimit = 100;
        limiter.Window = TimeSpan.FromMinutes(1);
    });
});

var app = builder.Build();

app.UseExceptionHandler();
app.UseHsts();
app.UseHttpsRedirection();
app.UseRateLimiter();
app.UseAuthentication();
app.UseAuthorization();

app.MapGet("/health", () => Results.Ok()).AllowAnonymous();
app.MapGroup("/api").RequireRateLimiting("default").MapOrders();
```

## Security

<Callout type="important" title="Baseline checklist">
- Fallback policy requires authentication.
- Resource-level authorization on every "load by ID".
- Rate limiting on public endpoints.
- `ProblemDetails` errors — no exception messages or stack traces in production.
- Secrets from a vault or environment, never from `appsettings.json` in source control.
- CORS lists explicit origins; never `AllowAnyOrigin` together with credentials.
</Callout>

<Warning>
Don't return exception messages to clients. They leak table names, file paths and library versions that make an attacker's job easier.
</Warning>

## Conclusion

A secure baseline is mostly about **defaults**: deny by default, validate by default, hide internals by default. Endpoints then only need to add the rules that are specific to them.
